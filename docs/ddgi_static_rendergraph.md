# DDGI on the static render graph — implementation roadmap

Status: proposed implementation sequence, not a claim of a functioning renderer. Each stage is independently reviewable; the integrator owns build, GPU verification and sign-off. Base: proposal/static-rendergraph-timelines.

## 1. Contract and scope
Start with one fixed axis-aligned world-space volume, 16 x 8 x 16 probes, 128 rays/probe, 8 x 8 directional irradiance bins and 16 x 16 distance-moment bins. Use linear HDR, metres, and a deterministic rotating spherical Fibonacci sequence. Disabled by default; no change to baked GI, AO, SSR or SSGI when disabled. Require SupportsRayQueries(), a valid scene TLAS, and valid shader/resources; otherwise use existing diffuse ambient. No change to specular IBL. Treat these initial settings as tuning values, not performance promises.

## 2. Resources and ABI
Add Engine/Rendergraph/ddgi.h and matching HLSL ABI. Own persistent irradiance (RGB plus validity) and distance (mean, second moment) buffers or atlases, separate read/write history, probe state (offset, classification, age), and ray scratch. Use checked 64-bit products before allocation; validate dimensions, spacing, max distance, ray count and device limits. Allocate/zero history explicitly; first update bypasses hysteresis. Use existing resource-manager holders, logical handles and shader library. Retire resources only after their last GPU use. Register hot reload and shader packaging; no ray-query module creation on unsupported devices. Keep BDA push structs aligned and assert size/offsets against HLSL. Prefer buffers with manual octahedral sampling first to avoid atlas seam/border ambiguity. If using textures, allocate one-texel mirrored oct borders and update them before sampling.

## 3. Graph and timeline
Inspect contact_shadow.h (Record, PassFrameData, AddImageHint) and giprobe.cpp (noncapturing static record functions). Insert after TLAS build and before Main:
1. DDGITrace: TLAS read, previous history read, ray scratch write.
2. DDGIBlend: scratch read, previous irradiance/moments read, next irradiance/moments write.
3. DDGIClassifyRelocate: scratch read, next probe state write; state offsets used on the NEXT trace only. Do not publish new offsets with irradiance computed at old positions; invalidate/reset moved probes on next update.
4. Main: sample published irradiance, moments and matching probe positions.
Declare every buffer/image access through graph hints, including BDA accesses, and explicitly connect TLAS build writes to ray-query reads using the RHI's existing acceleration-structure synchronization path. For initial integration use graphics queue compute and serialize history: wait for prior readers of a slot before overwrite, wait for prior history producer before trace, and signal after last consumer. A flight index alone is not a history lifetime guarantee. Do not CPU-wait every frame. Use static topology keyed on feature/volume allocation, not frame index, with dynamic handles/indices resolved in per-flight FrameData as supported by compiler. Record via SetRecordFn, no captured frame lambdas. Disable/reconfigure at a safe graph rebuild boundary. Only primary view updates; secondary views read the same completed version.

## 4. Ray trace and hit lighting
Follow engine/shaders/raytraced_sun_shadow.cs.hlsl: existing set 0 binding 8 TLAS, inline RayQuery, no FORCE_OPAQUE (opacity micromaps). Ray origin is probe position plus published offset, direction unit length, TMin positive, TMax configurable. Store direction, linear incident radiance, hit distance and front/back flag. For misses evaluate environment sky using the same physical units as Main, excluding direct sun disk if sun is evaluated separately. For hits resolve committed instance/geometry/primitive and barycentrics through a verified TLAS-to-GPU-scene mapping; interpolate position, normal, UV; use actual material base color/emissive and alpha handling. Do not infer that instance ID is draw index; verify RHI mapping including instanced and skinned meshes. Evaluate emissive plus Lambertian direct lighting (sun visibility via second ray and supported local lights), then optionally previous-history diffuse bounce with energy clamp. Never sample current write history in trace. An initial sky-only tracer is diagnostic, not accepted DDGI. For unsupported material types use a documented conservative fallback and count them.

## 5. Filter and temporal accumulation
For every irradiance bin decode oct direction n and integrate all rays: E(n) = 4*pi/N * sum(max(dot(n,rayDir),0)*Li). Backface samples contribute zero, not sky. Distance bins use directional weights pow(max(dot(n,rayDir),0), exponent); blend first and second moments, not variance. Clamp distances to max distance; miss contributes max distance. Guard zero weight, nonfinite values and negative variance. Blend old/new with hysteresis 0.95, first sample/reset uses 0. On abrupt lighting changes reduce hysteresis, avoiding long ghost trails. One writer per probe/bin; no atomics required. Rotate rays per update with deterministic seed. Start with all probes; later budget updates round-robin, copying unchanged history/state forward exactly.

## 6. Sampling and lighting
Implement a shared DDGI sampling helper, called by lit shader diffuse ambient and by probe hit lighting for previous history. For world point plus normal/view bias, locate eight neighboring grid probes; reject outside volume (fade in outer cell). Use trilinear weights, normal-facing weight and Chebyshev visibility using directional mean and second moment sampled toward receiver from actual probe position. Variance=max(m2-m1*m1,epsilon), visibility=1 for distance<=mean, otherwise variance/(variance+delta^2), sharpen and clamp. Skip invalid/inactive probes and normalize weights; if total near zero return invalid, not black. Evaluate irradiance toward surface normal; return E, not outgoing radiance. In Main replace the existing diffuse ambient slice with lerp(existing, kD*baseColor*E/pi, confidence*strength); preserve emissive, direct light and specular. Respect existing AO MRT accounting and diffuse SSGI replacement contract: choose one diffuse replacement owner or explicitly compose residual, never add both full terms. Baked GI fallback must remain valid outside volume. Inspect sg_gi_volume.hlsli and ssgi.h for current contracts. Extend C++/HLSL FrameUniforms in lockstep (all view builders, ABI asserts); invalid descriptor/address must never be dereferenced.

## 7. Relocation and classification
Use fixed diagnostic rays and committed front-face flag. For probes inside geometry (backface fraction > 0.25), move toward nearest backface exit plus clearance; for too-near frontfaces move away. Clamp offset to 0.45 * spacing from nominal location; invalidate history when movement exceeds tolerance. Mark probes inactive if no safe location; periodically retry, do not permanently starve after geometry moves. Publish state and irradiance consistently. Reset on scene replacement, volume origin/spacing/dim changes or shader ABI change; lighting-only changes use adaptive hysteresis.

## 8. User controls and observability
Add opt-in runtime switch, volume bounds/spacing, ray count, update budget, hysteresis, max distance, normal bias, strength. Hook editor and app settings without forcing project serialization changes in first milestone. Expose GPU timings for trace/filter/state, valid probe count, backface fraction, history age, invalid samples. Extend existing GI probe visualization (giprobe.h/cpp) with DDGI irradiance and classification modes; preserve baked modes. Debug views: irradiance only, visibility, relocation, fallback mask. Keep debug off by default.

## 9. Integrator acceptance gates (unchecked)
- [ ] Ninja Debug and Release App builds, shader compile/package, Benchmark build. Run ctest --test-dir out/build/x64-Debug --output-on-failure and python -m unittest discover -s tests -p "test_text_integrity.py" -v. Record exact commands, GPU/driver and commit.
- [ ] CPU unit tests: grid flatten/unflatten, oct encode/decode round trip (dot > 0.9999), constant incident radiance yields E approximately pi*L (within 5% at 4096 rays), moment variance nonnegative, first frame reset, zero weights, boundaries and checked allocation overflow.
- [ ] Vulkan validation + synchronization validation: zero DDGI-related warnings/errors across 1000 frames with >=2 flights, toggling, resize, scene reload, shader reload and multiple editor views. Capture dependency chain TLAS -> trace -> blend -> Main and history reuse.
- [ ] No ray-query GPU: feature disables gracefully, no invalid shader or descriptor access; disabled deterministic render matches baseline within capture tolerance (document tolerance).
- [ ] Constant environment with white Lambertian plane: compare E/pi to analytic L; <=5% mean error after convergence. Black environment/no emission yields no NaNs and near-zero DDGI.
- [ ] Closed opaque wall between bright and dark rooms: compare to reference; dark-side indirect leakage <=5% of bright-side mean at points at least one spacing from wall. Record geometry, spacing and camera.
- [ ] Dynamic colored emissive object and moving occluder: indirect color/occlusion responds, no stale geometry; after step change reaches 90% of new steady state within 60 full updates (tune adaptive hysteresis if needed).
- [ ] Probe in solid geometry is relocated within clamp or inactive; moving geometry allows recovery; no irradiance paired with wrong position.
- [ ] Outside-volume and all-invalid cases use baked/sky fallback; no seams or energy doubling with AO/SSGI, specular unchanged.
- [ ] Benchmark fixed camera, same cooked scene/settings, five runs each baseline/DDGI via tools/perf_harness.py. Report median frame time, DDGI pass GPU time, VRAM, ray throughput, CPU graph rebuild count. Suggested initial budget <=3 ms at 2048 probes x 128 rays on target GPU; integrator sets final device-specific budget before sign-off. No unbounded VRAM growth.
- [ ] Confirm graph topology reuse on steady frames and no per-frame CPU blocking wait. Capture hot reload and device shutdown lifetime correctness.

Do not merge as production-ready until the implementation stages and acceptance gates are satisfied. No tests or GPU captures have been executed by the author of this proposal.
