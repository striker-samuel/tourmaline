(Engine, RESOLVED) THE STRANDED-UPLOAD WRITE — a rendergraph sync sharp
edge where an UPLOAD's bytes were read by a draw in the same frame, even
though the frame's submit waits for the upload. Caught on device by
PlacementGpuTests' section 10 (the end-to-end pixels-on-device draw
proof, commit 370798dd): the publish frame's DrawIndexedIndirect read
indexCount == 0 (a SILENT no-op draw — no fault, no pixels) while the
POST-FRAME READBACK OF THE VERY SAME BUFFER showed the seeded
indexCount == 6 + the kernel's instanceCount == 69, with a reliable
one-frame lag (benign pop-in for streaming tiles, pinned as a contract
by the test).

ROOT CAUSE (the hint defect): the section-10 draw pass hinted the
indirect buffer with IndirectCommandRead @ PipelineStageBit_AllGraphics
— but the engine's AllGraphics maps to the SHADER-stage union ONLY
(ToVkStage, impl.cpp ~1511: Vertex|Fragment|Geometry|Tess|Task|Mesh ->
VERTEX_INPUT|VERTEX|...|TASK|MESH — never
VK_PIPELINE_STAGE_2_DRAW_INDIRECT). The barrier's dst stage therefore
EXCLUDED the fixed-function stage that fetches the command, so the fetch
was unsynchronized no matter who wrote the buffer. The production
pairing rule (gfx_filter's AddConsumeHints: "Engine helper covers
IndexRead@Vertex and IndirectCommandRead@DrawIndirect") is the contract:
IndirectCommandRead MUST pair with PipelineStageBit_DrawIndirect. The
test's hint is fixed; every hand-written indirect-draw hint must follow
that shape — now ENFORCED (see below).

  Historical barrier evidence (TOURMALINE_BARRIER_TRACE, pre-fix — note
  the dstStage=1807fc on the draw line: the missing 0x2 DRAW_INDIRECT
  bit WAS the defect):

    [RG] pass 'PlacementDrawBuild' ... barrier buf h=78:
        srcStage=1000(TRANSFER) srcAcc=1000 -> dstStage=800(COMPUTE)
    [RG] pass 'PlacementDraw'     ... barrier buf h=78:
        srcStage=800(COMPUTE)  srcAcc=60  -> dstStage=1807fc dstAcc=21

NOTE (the retired theory): the investigation's first explanation — that
the rendergraph loses upload visibility because its per-resource sync
state tracks only the LAST write's scope (the draw-build COMPUTE
re-write shadowing the TRANSFER seed, so no barrier ever delivered the
seed to the draw) — was DISPROVEN on device by PR2's reproducer: the
frame submit's transfer-timeline wait already establishes the memory
dependency to the whole waiting submission, so the narrowed graph-local
barrier src is NOT a visibility bug. The last-writer tracking, the
upload timeline semaphore, and the single-writer placement are all sound
as-is; no synchronization machinery change is needed or wanted.

The CONSUMER RULE ("never let a draw depend on bytes an UPLOAD wrote to
a buffer that a KERNEL re-writes in the same frame") is RETIRED for
placement (single-scope writer by construction); the write-debt union
alternative stays UNRESOLVED BY DESIGN — do NOT take the naive union
blindly:
  - A naive `state.masks |= req.barrierMasks` prototype was tried and
    BROKE OTHER PASSES: accumulated READ scopes produced access bits
    whose supporting stages were not in the mask (e.g. IndirectCommandRead
    with no DrawIndirect stage) — invalid (stage x access) pairings, the
    exact class the ingestion assert now rejects. Any union approach
    must track WRITE (stage, access) PAIRS only, never read scopes, and
    the debt must survive read passes until the buffer dies (a barrier
    delivers only to its own dst scope; later readers with a different
    scope each need their own delivery).
